# Produce an ambiance film

Use `./ambiance` from the studio root, with `--project PATH` before the command. Read [operations](../../../docs/OPERATIONS.md) for project handling and [quality gates](../../../docs/QUALITY-GATES.md) for evidence rules.

Author canonical creative intent with the [production plan](../../../docs/PRODUCTION-PLAN.md) and `plan spec inspect/check/apply`. Keep five-dimensional intent and expectations there, fulfillment in inventory, runtime in scene, and actual observations in reviews. Migrate legacy census notes explicitly with preserved originals; `plan complexity` reports workload, not artistic quality.

Use `plan coverage --stage layout|assets|animation|export` and `iteration preflight` for the shared readiness decision. Register actual typed evidence with `plan evidence`; keep unperformed observations unreviewed. Draft proof/review iterations remain presentable with gaps; `scope: final` requires the intended view/role set and applicable exact evidence. Captures bind canonical plan identities, so changed intent needs a new captured subject.

1. Locate the user's project with `project list`; registered IDs work across code worktrees. Read its brief, authored handoff and `project overview` for current movies, open criteria and available work. Use `project status` for detailed gate/revision evidence. For a new project, preserve the supplied image with `ambiance project init` and register its canonical location with `studio register PATH`. If the reference is attached without a usable local path, inspect it through the available image capability and preserve a returned local copy when supported; do not claim it was archived before it exists.
2. Inspect the reference and follow [seed-to-stage production](../../../docs/SEED-TO-STAGE.md): census the whole scene, choose story actions, plan portrait and landscape compositions, and identify the independent artwork/hidden paint they require. Explicit user scope overrides studio defaults. Read the [style guide](../../../docs/STYLE-GUIDE.md) as artistic guidance; preserve the seed's identity while composing for the requested outputs.
3. Use `doctor` to inspect local capabilities. Record target dimensions, picture cycle, audio/master cycle, assets and generation authority. Keep working masters short and complete; extended viewing belongs to playback or a separately requested delivery. Preserve all required actions/views. For TV targets, inspect source detail and internal raster limits before promising 4K. Continue local work if paid tools are unavailable; a plugin login does not establish API access.
4. Route the actual stage: image breakdown → `ambiance-deconstruct`; production art → `ambiance-assets`; scene/cels → `ambiance-animate`; soundtrack → `ambiance-sound`; final inspection and reusable archive → `ambiance-release`. Read only the relevant skill. These are workflow roles, not an instruction to spawn agents.
5. Maintain project records and reconcile the [production inventory](../../../docs/PRODUCTION-INVENTORY.md) with `plan inspect/check/next`. Mark selected requirements `required: true`; keep artistic stillness distinct from missing production work. A small prototype leaves the broader requirements open. Continue independent reversible work when another review is pending.

Bring the user a small number of meaningful creative decisions: the style/composition proof, the draft with sound, and the release review are useful defaults. Do not ask them to approve routine coordinates, file formats, or every generated cel. Respect a requested level of autonomy. Quality records must still distinguish agent review, actual user feedback, unperformed checks, and explicit exceptions.

For a workflow exploration, name the few capabilities the current cycle will demonstrate and show their concrete proofs. For full layered films, require [whole-object ownership and proof](../../../docs/LAYER-AND-LIGHT-PLANNING.md#whole-object-ownership-and-proof) before motion polish: complete characters, meaningful props/surfaces and clean surroundings, followed by internal articulation. A still body cannot be fulfilled by a neck patch or by imagery retained in a full-scene plate. Keep partial prototypes distinct from completed decomposition, and changing drawings distinct from light modulation.

Make a combined motion draft in the requested compositions before detailed polishing. Judge the intended story actions and environmental life at normal size/speed, then stability. Use `plan coverage` for the applicable canonical stage before calling production scope complete; attach actual picture observations separately. `plan check --require-complete` retains its narrower inventory-only meaning for unmigrated legacy projects. A labeled partial draft can be presented with its requirements still open. Record consequential scope reductions and capability gaps rather than silently defaulting to the seed's dimensions or fewer animated subjects.

Reuse compatible assets and rigs before generating replacements. Reconcile uncertain generation outcomes before retrying; preserve useful work and record cost/time only when known.

For a selected production version, use [revision capture and checks](../../../docs/REVISIONS.md), then bind renders, reviews and editions to that revision. Legacy folder-watch receipts remain unchanged; capture does not migrate their verdicts. Finish the requested scope with inspectable artifacts and a handoff. A planning or asset pass does not imply a final video.

When completing a movie iteration, follow the [studio library](../../../docs/STUDIO-LIBRARY.md): use `iteration run` for a saved capture/render/compose recipe, or `delivery import` and `delivery present` for existing verified outputs. Return both the exact-version watch link and the stable project-current link. Keep the current review separate from the working scene and approved release; scratch proofs and open human checks do not redefine that selection. Use `project latest` to answer which movie is current, and attach feedback to its exact version.

For requested portrait/landscape delivery, use the shared-stage [saved-view workflow](../../../docs/VIEWS.md). Record both crop intentions in the brief before art production. Use `project init --format dual` for a new blank stage, or adapt an existing scene explicitly through `view apply`. Produce the requested view/soundtrack Cartesian product with iteration schema 2 and return exact/current links for both orientations.
