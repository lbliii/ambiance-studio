# Audio levels and encoding

`audio measure` reads a selected **48 kHz mono/stereo integer PCM WAV** without changing it. Paths follow the existing project-relative audio input contract; an absolute contained source is also accepted. Use `audio source-prepare` for explicit source conversion first. Compressed audio is never silently decoded/resampled by the meter.

```sh
./ambiance --project PATH audio measure audio/preparations/source-v1/working.wav --source-sha256 HASH --out measurements.json
./ambiance --project PATH render video --audio MASTER.wav --audio-bitrate 320000 --out NEW_DIRECTORY
./ambiance --project PATH media compose PICTURE.mp4 --audio MASTER.wav --audio-bitrate 320000 --out NEW_DIRECTORY
```

The measurement result identifies exact source bytes, format, sample interval, meter/adapter hashes and Node backend/version. It distinguishes unweighted RMS and sample peaks from integrated LUFS and oversampled true peak. A native mono channel contributes once; stereo channels contribute independent energies. The separate `(L+R)/2` mono measurement reports complete cancellation explicitly, including a zero RMS ratio, even when stereo loudness is unchanged by polarity reversal.

Integrated loudness implements [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I) Annex 1 using its 48 kHz K-weighting coefficients, 400 ms blocks with 75% overlap, an absolute −70 LUFS gate and a second gate 10 LU below the absolute-gated result. Only complete blocks contribute. `silence`, `insufficient_duration` (non-silent clips shorter than 400 ms) and `below_gate` have a null LUFS value. A short event in a longer interval can contribute when its containing blocks pass the gate. The report gives block counts, gate values and excluded trailing samples. Null logarithmic levels mean unavailable or zero signal as described by status, never a fabricated finite floor.

True peak uses Annex 2's published 48-coefficient polyphase FIR at 4×/192 kHz in double precision. The finite selected interval is zero-extended; eleven source-rate frames flush the FIR support. This flush contributes no new loudness blocks. The result is a reconstruction estimate with finite-filter/oversampling limits, not the exact continuous maximum. The fixture suite implements [EBU Tech 3341](https://tech.ebu.ch/docs/tech/tech3341.pdf) deterministic definitions 1–5 (integrated, ±0.1 LU) and 15–19 (true peak, +0.2/−0.4 dB). This is not an EBU Mode meter or a full conformance certification; momentary/short-term meters, LRA, surround and other sample rates are outside this slice. The official recording archive could not be downloaded in this trial (HTTP 403); generated definitions do not substitute for real-programme or complete independent conformance testing.

Audio bitrate is in bits per second. Omission preserves the legacy request of **256000**. The bounded choices are 256000, 320000 and the trial 384000, subject to the native codec's format-specific capability. The backend queries `AVAudioConverter.applicableEncodeBitRates` for stereo 48 kHz before raster work; a globally available bitrate is insufficient. The 384000 trial was rejected on the recorded host, whose applicable list ends at 320000. Nothing selects another rate automatically. Each new native iteration's pending sound jobs are preflighted before its picture jobs; saved/recoverable outputs still use the existing integrity/recovery checks without requiring the encoder again. Injectable executors own their capability checks.

Iteration edition entries accept `audio_bitrate`; silent entries reject it. Composition recipes, render reports and new audio edition recipes/evidence carry resolved `audio_encoding`. Legacy receipts remain readable. The native standalone `audio INPUT OUTPUT [BITRATE]` and `compose VIDEO AUDIO OUTPUT REPEATS [BITRATE]` retain their old omitted-argument defaults. Requested bitrate and the decoded track's `estimated_encoded_bitrate_bps` stay separate: AAC can produce a lower average rate on simple material. Neither establishes perceptual quality.

The existing AVFoundation verifier keeps its presentation timestamp/sample selection. Alongside `decoded-audio.wav` (legacy PCM16 playback), it retains `decoded-audio.f32le` with unclipped interleaved float32 presentation samples. Measurements use that float stream, not clipped integer audio. The legacy playback WAV rounds/clamps the same float samples to PCM16, with its old PCM16 peak/RMS labels retained. Source PCM measurements and decoded AAC measurements are separate records with their respective file hashes. Encoded-source hash, raw decoded count, presented count and edit segments bind the latter to the exact movie interval; priming/padding outside the presentation interval does not enter the meter. AAC feeding now uses float32 PCM to avoid the former PCM16 intermediate; originals and selected PCM snapshots remain byte-exact. AAC bytes are not promised identical to the previous encoder adapter.

New audio editions pin the float artifact as `audio_presentation_float`, along with the existing media report, source snapshot, recipe and encoded movie. Changed decoded bytes stale the edition dependency. No visual-model record or new rendering/evidence authority is introduced.

Decoded headroom is reported against a **provisional −1 dBTP ceiling** as `within`, `exceeds` or `silent`. It is an engineering observation, not a delivery pass or a platform-mandated target. No automatic normalization, universal ambiance LUFS target, source promotion, listening comfort judgment or audition is inferred. Original WAV and encoded AAC auditions remain separate, unperformed observations unless explicitly recorded elsewhere against exact files.
